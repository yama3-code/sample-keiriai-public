# 公開前に確認すること

更新：2026-11-03

アプリ側の安全対策を実装した状態です。インターネットへの公開や、実際の会社の資料を使う前には、以下の外部設定と実環境での確認が残っています。

解説サイトだけの公開は、経理AIシステム本体の公開と分けています。`vercel.json` は `npm run build:guide` の静的出力だけを公開し、業務API・マスタ編集・APIキー・Redisを含めません。解説は全ページのnoindexと応答のX-Robots-Tagで検索からの除外を指定します。robots.txtの巡回を禁止するとnoindexを確認できないため巡回自体は許可します。これは閲覧制限ではなく、URLを知っている人は読めます。以下のClaude・Redisなどの確認は、経理AI本体を公開する場合に必要です。

解説の公開先は [経理AIのしくみ](https://sample-keiriai-guide.vercel.app/guide/)。2026-11-03に本番の表紙と全12章でHTTP 200、HTMLのnoindex、X-Robots-Tagを確認しました。業務API・編集・マスタ・秘密設定・サイトマップは404です。公開はVercel CLIで静的出力だけを送信し、GitHubの自動デプロイ連携は設定していません。

## APIキーとGitHubへの保存

- 開発用の保存先は非公開です。`.env.local` と `.local/` はGitから除外し、過去の履歴にも環境設定や既知のキー形式がないことを検査しています。非公開リポジトリにも秘密の値は保存しません。
- 手元の `.env.local` は `chmod 600 .env.local` で本人だけが読み書きできる権限にします。Claudeの接続はサーバー専用にし、公式APIへの接続先を固定、SDKの詳細ログを無効にしています。公開用の変数名にキーやトークンを入れないでください。
- `npm run check:secrets` は現在のGit対象、`npm run check:secrets -- --history` は全履歴を検査します。値を出力せず、実際の環境設定を読み込んだり、外部へ送信したりしません。
- この作業フォルダでは `npm run security:install-hooks` でGitの検査を有効にします。新しい作業フォルダでは再度実行が必要です。コミット前は実際に追加済みの内容、送信前は履歴を検査します。GitHub Actionsの検査は送信後の補助であり、送信前の阻止ではありません。検査の無効化や、未知の形式・すべての秘密を防ぐものではありません。
- GitHubの依存ライブラリの脆弱性通知は有効化済みです。組み込みの秘密情報スキャン／送信阻止は、この個人所有の非公開リポジトリでは有効化を確認できていません。プランやリポジトリの種類で提供範囲が異なるため、有料プランを追加せず、手元の検査とGitHub Actionsを用意しています。[GitHub公式の提供範囲](https://docs.github.com/en/code-security/concepts/secret-security/about-alerts)。

### キーを誤って共有・送信した場合

1. Claude Consoleで対象のキーを無効化します。削除・無効化は実行中の処理へ影響するため、対象を確認して行ってください。
2. 新しいキーを発行し、手元の `.env.local` と、公開している場合は公開先のサーバー設定を差し替えます。キーをチャットで受け渡ししません。
3. アプリを再起動し、公開先では必要な再デプロイを行います。Claude Consoleで利用履歴と月額上限も確認します。
4. GitHubへ送信済みなら、古いキーの無効化を優先し、対象の履歴やコピーの扱いを確認します。現在のファイルから消しただけで解決したとは扱いません。

今回、漏えいしたキーは検出しておらず、既存キーの無効化・再発行や課金設定の変更は行っていません。月額上限の確認は引き続き下記の本人操作が必要です。

## 1. Claude APIの月額上限

今回、Anthropicの管理画面の上限・通知設定は確認・変更していません。アプリの回数制限は、金額の上限ではありません。

1. [Claude ConsoleのWorkspaces](https://platform.claude.com/settings/workspaces) を開き、このアプリのAPIキーが属するワークスペースを確認します。ほかの業務と分けた専用のワークスペースを推奨します。
2. 対象のワークスペースを選び、`Spend limits` で許容できる月額上限と通知のしきい値を設定・確認します。
3. 公開先で使うキーが、その上限を設定したワークスペースに属することを確認します。キーをチャットや画面に貼って共有しないでください。

設定場所と上限の説明：[Anthropic公式 Workspaces](https://platform.claude.com/docs/en/manage-claude/workspaces)。この作業では月額予算を勝手に決めたり、課金設定を変更したりしていません。

## 2. 公開用の既定値

公開環境（`NODE_ENV=production` またはVercel）では、以下をサーバー側でも適用します。手元の開発では従来のモデル選択を維持しています。

| 項目 | 公開時の既定値 |
| --- | --- |
| 選べるモデル | Haiku 5.5／Sonnet 5.5 |
| 選べるエフォート | 低／中 |
| 初期選択 | Haiku・低 |
| 新しい依頼 | 全体で毎時5回・24時間10回 |
| 同じ接続元 | 新しい依頼は毎時3回。同じ会社の回線では共有 |
| 同じブラウザ | 新しい依頼は毎時5回 |
| 1回の回答量 | 最大8,000トークン |
| 1回のClaudeとの往復 | 最大6回 |
| API側の自動モデル切替 | 無効 |

環境変数の見本は `.env.example`、許可範囲は `lib/usage-policy.ts` です。ブラウザからの直接送信・過去の再開券でも許可範囲を広げられません。

## 3. 公開用Redisと入口の大量アクセス対策

今回の確認では、手元に公開用Redisの接続情報は設定されていませんでした。実接続は行っていません。

- 公開先に `UPSTASH_REDIS_REST_URL`・`UPSTASH_REDIS_REST_TOKEN` を設定します。開発・プレビュー・公開ごとに `SECURITY_STORE_PREFIX` または保存先を分けます。
- 架空データで、設定保存・履歴復元・同時送信・回数超過・障害時の停止を実環境で確認します。実施時には一時的な専用領域を使い、業務中の記録や上限をリセットしません。
- 公開先でもヘッダーが付くことを確認します。アプリ外の大量アクセス制限は、公開作業時に設定・確認します。今回、Vercelの管理画面やファイアウォール設定は変更していません。

アプリ内では、不正な送信は1分単位の入口制限で扱い、受け付けた操作だけを時間・日単位の業務枠に数えます。ただし、匿名で使える以上、複数の接続元から正しい依頼を送って利用枠を消費する行為を完全には防げません。

公開前に、利用できる接続元を社内回線などに絞る方針を決めてください。公開先の [Vercel WAF Custom Rules](https://vercel.com/docs/vercel-firewall/vercel-waf/custom-rules) では接続元などの条件による拒否・回数制限を設定できます。今回、公開範囲や外部サービスの設定は変更していません。同じ社内回線では全員で毎時3件の新規依頼枠を共有します。

## 4. 資料の保持期間

| 対象 | 現在の扱い |
| --- | --- |
| 元のアップロード | 2時間の期限を指定。通常の終了時にも削除を試みる |
| Claudeの作業用環境内のコピー・計算結果 | Anthropic公式では最大30日の保持。元添付を削除しても、こちらの即時消去を保証するものではない |
| コード実行で作られたFiles APIの成果物 | 通知されたIDを取得直後から削除対象にする。失敗分は会話・終了処理でも再試行するが、削除失敗・ID通知前の切断・画面終了通知の未達時に自動消去の期限は保証しない |
| アプリ内の会話 | ページ内のメモリだけ。再読み込み後の再開や、恒久保存はしない |
| マニュアル・マスタの変更履歴 | 直近10版・容量上限まで。別枠の固定控えは繰り返し保存で削除・差し替えされない。どちらも全員が閲覧でき、削除前のマスタも残る場合がある |

保持条件の根拠：[Anthropic公式 Code execution tool — Data retention](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool#data-retention)。今回は実際のClaude APIでの削除や保持期間の観測はしていません。

会社の実資料を使う場合は、この保持期間と、誰でも閲覧・編集できる公開範囲が会社の扱いに合うかを確認してください。ログインなし・誰でも編集できる仕様は維持しています。履歴と復元は、書き換えを禁止する権限管理ではありません。

### 設定を戻すとき・手元の控えを残すとき

1. 大きな変更前と、少なくとも設定を変更した日の終了時に、「変更履歴と復元」の「現在の設定を書き出す」を押します。日付入りのJSONを、社内の公開しない保管先に世代を分けて保存します。内容が正しいことも確認してください。
2. 書き換えが見つかったら「編集する」から、保護した控え・最近の履歴・初期値のどれに戻すか選びます。違いを読み、確認欄にチェックして復元します。削除済みマスタが戻る場合があります。
3. 保護した控えは初回保存前の内容です。既存の保存がある場合は、次の保存時に残存する最古の履歴（なければ現状）が固定されます。すでに消えた履歴を復活させるものではありません。控えを新しい内容へ更新する公開操作はありません。
4. 最近の履歴からの復元は、通常保存と合わせて接続元30回／全体60回の1時間枠に数えます。連続操作には接続元5回／全体10回の1分枠もあります。初期値・固定控えへの復旧だけは別枠で、接続元5回／分・10回／時、全体10回／分・20回／時です。復旧自体の枠が満杯なら待ち時間が表示されます。継続的な妨害時は公開先で接続元を制限する必要があります。
5. 書き出したJSONは手動で入力し直すための控えです。直接取り込みには対応していません。固定控えと設定は同じ保存先にあるため、保存先全体が壊れた場合に備え、手元の書き出しも保管してください。

復元では最近の履歴を追加・削除せず、最終更新日時を更新します。通常保存では、初期値・固定控えに戻すための容量も確保します。ただし、旧形式から初めて固定控えを作る移行では履歴を整理する場合があります。容量を確保していない古い保存や、同梱初期値が変わった場合に復元が収まらなければ、履歴を消さずエラーで止めます。まず設定を書き出して保管し、管理者に確認してください。

新規保存では改行・タブ以外の制御文字を拒否します。既存の保存内容は書き換えず読み込めますが、制御文字を含む通常履歴の版はそのまま再適用できません。内容を控え、編集画面で文字を取り除いて保存してください。旧データの固定控えからの明示的な復旧は維持しています。

## 5. 確認済みの範囲

- 模擬API・一時保存先の安全対策テスト129件が成功。大型8回／小型12回の保存後も固定控えが残ること、通常保存枠満杯後の初期値復旧と荒らし版の再適用拒否、交互復元で履歴が増減しないこと、復旧の分・時間上限、制御文字の拒否、巨大な旧設定の復元を確認。
- 型チェック、コード検査、公開用ビルドを確認。
- パソコン1280px／スマホ375pxで、変更履歴の確認・復元後の履歴保持と「現在の内容」の表示、新しい回数枠の説明、マスタ閲覧中は復元できないことを確認。横はみ出しなし。設定JSONのダウンロードと外部リンクは前回確認済み。
- 実際のClaude APIへの追加呼び出し・実ファイル送信・公開は行っていません。
