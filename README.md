# 経理AIエージェント（株式会社サンプル商事・ダミーデータ版）

「AI経理エージェント」に自由な経理の依頼を入力し、CSV・Excel・PDF・画像を渡すと、Claude が集計・照合・チェック・仕訳案の作成を行うWebアプリです。
決まった作業マニュアルを使う従来の3業務にも対応しています。
会社名・データはすべて架空です。

ログインは不要です。通常の業務画面は閲覧・実行用で、文言や手順を変えるときだけ右上の「編集する」を押します。

## AI経理エージェントの使い方

1. 業務一覧から「AI経理エージェント」を選びます（最初に表示されます）。
2. 必要なファイルを追加します。**最大15個・1ファイル3MBまで**。CSV、Excel（xlsx・xls）、PDF、画像（PNG・JPEG・WebP）に対応します。
3. 「依頼内容」に、してほしい作業と、ほしい結果を書きます。例：「売上明細を月別・部門別に集計して、重複や空欄を一覧にしてください。仕訳は不要です」。
4. 「AI経理エージェントに依頼する」を押すと、添付を1個ずつ送ってから作業を始めます。添付なしでも依頼でき、サンプルデータは使いません。
5. 報告書・表・作業ログ・要確認事項を画面で確認します。報告書はテキスト（.txt）、表はCSVで保存できます。報告書の保存先で画像やHTMLを自動表示させないため、保存はテキスト形式にしています。仕訳を依頼した場合は、仕訳CSVとプログラムによる検算結果も表示します。

- 依頼文は最大10,000文字。表は最大10表、1表500行30列、全体15,000セルまでです。大きな結果は要点に絞って報告します。
- ExcelやPDF・画像の読み取りが不確かな場合、推測で確定せず質問・要確認に回します。暗号化ファイルや読み取れないファイルの処理は保証しません。
- 計算はClaudeのコード実行ツールで行います。AIと別のプログラムによる検算の対象は、仕訳の貸借・科目などです。一般の集計表の業務上の正しさは担当者が確認します。
- 添付は送信元のブラウザと会話に結び付けます。同じ会話の追加依頼では元の資料を引き継げます。別のブラウザ・別の依頼への使い回しや、同じ送信の繰り返しは拒否します。

### 結果が出た後に、修正・追加を依頼する

1. 結果の下にある「この結果への追加依頼」に、続けてしてほしいことを書きます。例：「交通費だけに絞って、部門別の内訳も追加してください」。
2. 「追加依頼を実行する」を押します。最初の依頼・元の資料・途中の質問と回答・以前の結果を引き継いで作業します。修正や再確認では、必要に応じて元資料から計算し直します。
3. 質問が出たら回答して再開します。進み具合と中止の操作も従来どおり使えます。
4. 「第1回」「第2回」…の順に依頼と結果が残ります。それぞれの報告書・表・仕訳を保存でき、保存するファイル名にも回数が付きます。
5. 別の依頼に変えるときは「新しい依頼」を押します。前の会話・添付・結果を画面から取り除き、元資料の削除を依頼します。必要な結果は先に保存してください。

- 対象は自由に依頼する「AI経理エージェント」だけです。定型の3業務の操作は変わりません。
- 継続できるのは**同じ画面を開いている間だけ**です。再読み込み・画面を閉じる・別の業務や設定画面への移動で続きを失います。履歴を翌日再開する機能はありません。
- 継続期限は**初回開始から最長2時間**です。添付資料やClaudeの実行環境の期限が先なら、その時点で終了します。結果の下に実際の期限を表示します。資料を利用できない場合は、前の結果だけで続けず「新しい依頼」から送信し直します。
- **初回を含め6回（追加は最大5回）**、会話は**100発言・1MB**までです。発言数にはAI・ツールのやりとりも含むため、長い作業では先に履歴量の上限に達することがあります。
- 1回の依頼は**質問への回答待ちを含め5分・質問5回**までです。Claudeとの往復は手元の開発では12回、公開時の既定値は6回です。回答しても時間・往復の上限は戻りません。追加依頼を始めたときだけ、この1回分の枠を新しくします。
- 追加依頼も新しい業務実行として回数・同時実行の制限に含めます。毎時5回のブラウザ単位の制限が先に適用されることもあります。
- 追加依頼中の資料追加・モデル変更はできません。資料や設定を変える場合、または途中でマスタ・業務ルールが更新された場合は、新しい依頼から始めます。

定型業務（PC経費配賦・旅費・四半期決算整理）は、入力データの種類ごとに「ファイルを追加する」から複数のCSVを選べます。**業務全体で選択するCSVは合計10個まで・1ファイル1MBまで**です。選択後も1個ずつ外せます。未選択の種類にはサンプルを使います。実行時に1個ずつ送信し、全件をまとめて処理します。ファイル名ごとの処理件数・金額・保留理由と、仕訳摘要への元ファイル名・元行番号の記載をAIに指示します。別期間や重複したデータ、参照マスタの不一致は担当者への質問か要確認として扱います。

## しくみ

1. 画面で業務を選び、ファイルと依頼内容を送る（従来の3業務はCSVのみ。選ばなければサンプルデータを使用）
2. サーバーが元データを Claude のコード実行環境に渡す
3. Claude が作業マニュアルを読み、**計算はすべてPythonのコードで**行いながら手順を進める
4. マニュアルや規程に書かれていないこと・データの不備は、仕訳にせず「要確認事項」に回す
5. 結果を受け取ったら、アプリ側のプログラムでも**貸借一致・勘定科目・部門・日付を検算**する
6. 画面に報告書や表、仕訳を表示し、必要な結果をダウンロードできる。CSVはExcelで開けるBOM付きUTF-8

## 実行の設定

- **AIモデル**：手元の開発ではHaiku 5.5／Sonnet 5.5／Opus 5.5／Fable 5.1から選べます。公開時はHaiku／Sonnetだけで、初期値はHaikuです。公開用の許可範囲は `lib/usage-policy.ts` でサーバー側でも確認します。
- **エフォート（考える深さ）**：手元では低／中／高／最高／最大。公開時は低／中だけで、初期値は低です。上げるほど処理量が増えるため、公開時の出力量・往復回数も制限します。
- **途中の質問**：オンにすると、エージェントが判断に迷ったときに作業を止めて質問してくる。回答すると続きから再開する（1回の作業で最大5回）。質問と回答は作業ログに残る
  - 回答待ちのあいだ、途中経過はブラウザ側で預かり、改変検知・再送防止用の情報だけをサーバーに保存します。同じブラウザで1回ずつ再開でき、ページを再読み込みすると途中経過は消えます。定型3業務は開始から2時間以内、自由な依頼は上記の1回5分と会話の継続期限の両方を満たす必要があります。

## 文言・ルールの編集

1. 業務画面の右上にある「編集する」を押します。
2. 編集したい業務、または共通の「経費精算規程」を選びます。
3. 業務名・説明・補足指示の入力例・作業マニュアル、または経費精算規程を編集します。
4. 「変更内容を確認する」で変更前・変更後を見比べ、「この内容で保存する」を押します。
5. 「業務に戻る」で戻ると、保存した文言が表示されます。次の実行からClaudeも新しい手順・規程を使います。

- 誰でも編集できます。保存した内容は、すべての利用者に共通で反映されます。
- 保存前に項目を切り替えたり画面を離れたりするときは、変更を取り消すか確認します。
- ほかの画面で先に保存された場合は上書きせず、最新の内容の読み込みを案内します。
- 業務の途中でルールが変わった場合は、古いルールで再開せず、最初からの実行を案内します。
- 編集内容は元ファイルと分けて保存するため、再起動しても残ります。勘定科目表・部門マスタ・入力CSV・プログラムそのものは、この画面では変更できません。

## 業務の追加方法

`tasks` フォルダに、業務ごとのフォルダを1つ追加するだけで、画面に業務が増えます。
いちばん簡単なのは、既存のフォルダをコピーして中身を書き換える方法です。

```
tasks/
  04-新しい業務/          ← フォルダ名の番号順に画面に並ぶ
    task.json            ← 業務名・説明・入力データの設定
    manual.md            ← 作業マニュアル（Claudeはこれに従って作業する）
    samples/
      元データ.csv        ← サンプルデータ（task.json の file と同じ名前）
```

### task.json の書き方

```json
{
  "name": "業務の名前",
  "summary": "画面に表示する、業務の短い説明",
  "inputs": [
    {
      "id": "data1",
      "label": "画面に表示する入力データの名前",
      "file": "data1.csv",
      "description": "どんなデータかの説明"
    }
  ],
  "instructionPlaceholder": "例：対象月は2025年12月です"
}
```

- `inputs` は何個でも並べられます。`id` は半角英数字で、業務の中で重複しないようにします。
- `file` はサンプルデータのファイル名です。担当者が別のファイルを選んだ場合も、Claude にはこの名前で渡されます。
- 省略時の `mode` は `journal`（定型の仕訳業務）です。自由な依頼と複数形式の添付を扱う場合は、`mode: "general"`・`inputs: []` とし、`tasks/00-ai-keiri-man` のマニュアルを参考にしてください。

### manual.md（作業マニュアル）を書くコツ

- 「手順1」「手順2」…と番号を付けて、順番に書く（画面の進み具合にも手順名が表示されます）
- 計算方法（端数の扱いなど）、仕訳の借方・貸方の科目、伝票番号・日付・摘要のルールを具体的に書く
- 「こういう場合は仕訳にせず要確認とする」という止める条件を書いておくと、勝手な判断を防げます
- 科目は共通データの勘定科目表（`data/accounts.csv`）にあるものを使う。新しい科目が必要なら、先に勘定科目表へ追加する

## 安全対策と公開時の設定

- Claudeの接続はサーバー専用の `lib/claude-client.ts` に集約し、公式の接続先を固定、SDKの詳細ログを無効にしています。キーを画面へ渡す公開用変数にはしません。手元の `.env.local` は本人だけが読める権限にし、コピーやバックアップも公開しない場所へ保管してください。
- 依頼者の指定によりログインは設けていません。公開した場合は、誰でも業務の実行とルールの保存ができます。「編集する」は操作を分けるメニューで、編集者を制限する認証ではありません。
- 公開時の新しい依頼は、既定で1時間に1ブラウザ5回・同じ接続元3回・全体5回、全体24時間に10回までです。同じ会社の回線では接続元の枠を共有します。手元の開発では毎時1ブラウザ5回・同じ接続元5回・全体10回、全体24時間30回です。
- 質問への回答を含む受け付けた実行は、毎時1ブラウザ30回・同じ接続元30回・全体60回までです。期間は最初の試行から数えます。ブラウザの識別を変えても、接続元と全体の制限は維持します。
- 不正な送信を止める入口の制限と、受け付けた操作の利用枠は別です。入口は同じ接続元から1分に実行30回・添付90回・設定取得／保存30回・復元先の確認／復元30回・会話終了60回で、各全体枠はその10倍です。設定と復元の入口も別枠です。不正な本文・古い版・送信済みの券・個別上限による拒否では、ほかの利用者と共有する時間単位の業務枠を減らしません。複数の利用枠は一括で確認・更新します。
- 同時実行は1ブラウザ1件・アプリ全体2件までです。公開時は既定で1回8,000トークン・6往復、手元は32,000トークン・12往復です。公開時のAPI側自動モデル切替は使いません。通信中止時にはClaudeへの通信も中止しますが、それまでに発生した利用料は取り消せません。
- 編集の保存と最近の履歴からの復元は、合わせて1時間に同じ接続元から30回・全体60回までです。履歴復元には同じ接続元5回／分・全体10回／分の上限もあります。初期値・固定控えへの復旧だけは別枠で、同じ接続元5回／分・10回／時、全体10回／分・20回／時です。通常保存の上限に達しても、この復旧枠の範囲で戻せます。別サイトからの意図しない送信や、許可していない設定項目の変更を拒否します。
- 会話の終了は1時間に1ブラウザ30回・同じ接続元60回・全体120回までです。ブラウザの識別情報を変えても、接続元と全体の制限は維持します。
- マニュアル・手順や規程のプレビュー・報告書では、画像とHTMLの埋め込みを表示しません。外部リンクは行き先と送信の注意を表示し、確認操作の後だけ別タブで開きます。不正なURL・長すぎるURL等は開けません。画面内リンクは維持します。
- 編集画面とマスタ設定に「変更履歴と復元」があります。最近の履歴は直近10版・容量上限までです。別枠の「保護した控え」は通常の保存を繰り返しても消えず、アプリ同梱の初期値にも戻せます。控えは最初の保存前の内容です。更新前から保存がある場合は、残っている最古の履歴（履歴がなければ現状）を次の保存時に固定し、以後は差し替えません。既に消えた過去版は取り戻せません。
- 復元前に現在との違いを確認し、確認欄にチェックして実行します。手順・規程・マスタがまとめて戻り、削除済みのマスタも戻る場合があります。通常の読込で削除済みマスタを補うことはありません。復元では新しい履歴を追加せず、最終更新日時を更新します。マスタ画面では「編集する」の後だけ実行できます。履歴・控えは全員が閲覧でき、編集者を制限する機能ではありません。
- 復元時は既存の履歴を減らさず、保存済みの本文を参照して容量を抑えます。通常保存の時点で初期値・固定控えへ戻す容量も確保します。古い形式から初めて固定控えを作る移行では履歴整理が入る場合があります。以前の保存やプログラム更新により復元に必要な容量が足りない場合は、履歴を消さずエラーで止めます。
- 新しい手順・規程・マスタの保存では、通常の改行・タブ以外の制御文字（目に見えない特殊な文字）を拒否します。既存の保存内容は勝手に削除・置換しません。制御文字を含む最近の履歴を戻す場合は、内容を控え、編集画面でその文字を取り除いて保存してください。
- 「現在の設定を書き出す」で、保存済みの手順・マスタをJSONファイルに残せます。大きな変更前と定期的に書き出し、日付別に保管してください。手動で入力し直すための控えであり、ファイルの直接取り込みには対応していません。設定と控えは同じ保存先なので、保存先全体の障害への備えにも書き出しが必要です。
- 他サイトへの画面埋め込み禁止、外部への自動通信の制限、参照元の送信抑制などのHTTPヘッダーを設定しています。Next.jsのPPRと両立する静的CSPを採用し、インラインスクリプトの許可は残るため、表示部品の検証も引き続き必要です。
- 数式として解釈される文字列が仕訳の文字項目にある場合、CSVを作らずエラーで停止します。会計ソフトへ渡す文字を勝手に書き換えないための対策です。
- AI経理エージェントの表に数式として扱われる文字がある場合、その表のCSV保存だけを停止し、内容は画面で確認できます。通常の負数は数値として保存できます。
- 添付の送信は1時間に1ブラウザ75件・同じ接続元75件・全体150件、全体で24時間450件までです。サーバーでも個数・サイズ・拡張子と形式を確認します。
- 回数制限は定額の料金上限ではありません。公開時にはClaude API側の利用額上限も設定してください。

公開用の既定値は、サーバーの `PUBLIC_*` 環境変数で指定範囲内だけ変更できます。入力ミスでは制限を解除せず停止します。キー名と既定値は `.env.example`、月額上限や公開前に残る確認は [公開前の確認](docs/PUBLIC_READINESS.md) を参照してください。

開発用ツールの `minimatch` 10.2.6は11.0.4に更新済みです。`npm audit` には旧3.1.5とその利用元に関する中程度の警告が15件残りますが、公式説明にある問題の処理は旧3系にありません。互換性を維持するため、旧3系はそのまま残しています。公開時に使うライブラリだけの検査（`npm audit --omit=dev`）は警告0件です（2026-11-03確認）。

手元の `npm run dev` では、編集内容とその変更履歴・回数制限・再開券の検証値・一時的な添付情報（ファイル名・Claude側の識別番号など）を `.local/` に保存します。添付ファイル本体や依頼・結果・会話の履歴は保存しません。このフォルダはGit管理と公開用ファイルから除外しています。複数のプロセスで同時に使っても、更新の競合を防ぎます。

Vercelで公開するときは、Vercel MarketplaceでUpstash Redisを接続し、上記のURLとトークンをサーバーの環境変数に設定してください。開発・公開・プレビューでは保存先または識別名を分けます。`npm run start` も公開用の動作なのでRedisが必要です。公開用のコードには手元のファイル保存処理を含めません。保存先が未設定・停止中のときは、安全対策を解除せず、503（利用できない状態）で停止します。Redisの実接続は公開準備時に確認してください。

手元で保存処理中に強制終了し、`.local/security.lock` が残った場合は、アプリをすべて停止してからそのフォルダだけを削除してください。`.local/security.json` を削除すると編集内容と回数制限もリセットされるため、通常は削除しません。

安全対策の確認は、API料金を発生させずに実行できます。

```bash
npm run test:security
```

秘密情報の混入は、次の無料の検査でも確認できます。値や該当行は表示せず、ファイル名と検出理由だけを表示します。実際の環境設定を読み込んだり、外部へ送ったりしません。

```bash
npm run check:secrets
npm run check:secrets -- --history
```

新しくGitHubから取得した作業フォルダでは、`npm run security:install-hooks` を一度実行してください。このフォルダのコミット前は保存対象の内容、送信前は過去の履歴を検査し、問題があれば停止します。GitHub Actionsでもファイルと履歴を検査しますが、こちらは送信後の検知です。`.env.example` の秘密設定欄は空のままにします。既知の鍵形式と一部の設定名を調べる仕組みなので、すべての秘密を検出できる保証はなく、フックを無効化した操作も防げません。

誤ってキーを送信した場合は、ファイルから消すだけでは足りません。発行元で古いキーを無効化して新しく発行し、手元と公開先の設定を差し替えます。具体的な手順は [公開前の確認](docs/PUBLIC_READINESS.md) を参照してください。

## ローカル（自分のパソコン）での動かし方

初めての方は、解説サイトの「くわしく読む」→「実際に使う準備」（`/guide/detail/setup-overview`）に、道具の準備からAPIキーの設定・試運転までの手順と例をまとめています。

1. `.env.local` に `ANTHROPIC_API_KEY`・`ANTHROPIC_MODEL` を書いて保存する（見本は `.env.example`）。Macでは `chmod 600 .env.local` で本人だけが読み書きできる権限にします。手元の開発ではRedisの設定は不要です。以前の `APP_PASSWORD` が残っていても使いません。
2. ターミナルで次を実行する

   ```bash
   npm run dev
   ```

3. ブラウザで http://localhost:3000 を開く（ログイン不要）。開発サーバーは127.0.0.1だけで待ち受け、同じネットワークの別PCへ公開しません。
4. 終わるときはターミナルで `Ctrl + C` を押す

## 注意

- 1回の実行に1〜3分かかります。Vercel では最大5分まで待つ設定にしています。
- 作成された仕訳は、必ず担当者が確認してから会計ソフトに取り込んでください。
- 自由な依頼では、追加依頼の受付中も元資料をAnthropic側に残します。「新しい依頼」・質問の中止・処理失敗・回数や履歴量の上限到達時には削除を試みます。定型3業務は従来どおり結果の提出後に削除します。
- 元添付のアップロードには2時間の期限を設定しています。これは作業用環境内のコピーの消去期限ではなく、作業用環境のデータはAnthropic側で最大30日保持されます。コード実行が生成したFiles API成果物は、取得直後・終了時に削除を試みますが、削除失敗やID通知前の切断時に自動で消える期限は保証できません。アプリに資料本体や会話を恒久保存する仕組みはありません。実資料の利用前に保持条件を確認してください。

## マスタ設定（共通データの管理）

業務画面の右上「マスタ設定」→「編集する」から、共通データを追加・差し替え・削除できます。変更後は「変更内容を確認する」→「この内容で保存する」を押します。保存前は業務に反映されず、キャンセルできます。

- CSV・Excel（xlsx・xls）・TXT・MDに対応。Excelは2MB、CSV・TXT・MDは200KB（UTF-8／Shift_JIS）。保存する本文は50,000文字まで。全体20件・本文合計150,000文字まで。
- 勘定科目表は「科目コード・科目名」、部門マスタは「部門コード・部門名・人数」の列が必要です。空欄や重複を保存前に確認します。
- 勘定科目表・部門マスタ・経費精算規程は各1件まで。「その他の共通資料」は複数登録できます。
- 差し替えたマスタはAIの参照と仕訳検算の両方に反映します。削除したマスタは使わず、必要な情報がなければ要確認にします。
- 編集済みの経費精算規程は引き継がれます。業務ルール編集画面からの規程編集も同じ保存内容に反映されます。
- 保存内容は開発時は `.local/`、公開時は既存のRedisに保持し、再起動後も残ります。他画面との同時編集は版番号で検知します。

### Excelからのマスタ取り込み

「ファイルから差し替える」で `.xlsx` または `.xls`（2MBまで）を選び、「取り込むExcelシート」から対象を選んで「このシートを取り込む」を押します。1回につき1シートをCSVの内容に変換して表示します。「変更内容を確認する」→「この内容で保存する」で反映されます。別シートを追加資料として使う場合は、共通データを追加して同じファイルから別のシートを取り込んでください。

- 1行目を列名にしてください。コードの表示形式（例：001）も取り込みます。
- 数式はExcelで「値として貼り付け」に置き換え、結合セルは解除してください。数式・エラー値・結合セルがあるシートは取り込みません。
- 10,000行・100列・100,000セル以内、CSV変換後50,000文字まで。非表示・空のシートは対象外です。パスワード付きブックは解除してください。
- Excelの読み込み・変換はブラウザ内で行い、保存するのは選択したシートの値です。元のブック・書式・マクロは保存しません。CSV・TXT・MDは従来どおり200KBまで読み込めます。
